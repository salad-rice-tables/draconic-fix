# Spell audit (hero pool)

Generated by `tools/proxy_spells.py` (hotfix push 1903300).

## What was wrong
A pool spell is a copy of a retail spell with its own id. A copy loses everything the server attaches to the retail id: C++ spell scripts (`spell_script_names`), proc rules (`spell_proc`) and linked spells (`spell_linked_spell`). Such spells did nothing or only half (Stealth, Shear without Soul Fragments, ...).

## Fix: proxy spells
A proxy keeps its own id, name, icon, Essence cost, cooldown and global cooldown, but its only effect is *cast the original retail spell* (TRIGGER_SPELL). All scripts, procs and auras of the original therefore work as on retail.

* 185 existing pool spells with a script, proc or linked spell were switched to proxies (`data/proxy_converted.csv`).
* 507 class spells that were missing from the pool were added as proxies (`data/proxy_map.csv`), taken from the retail class trees.

## Known limits
* A proxy that depends on a *companion passive* (for example Shear needs the passive Shear proc 203783 to create Soul Fragments) still needs that passive on the player. Not done automatically.
* Passive spells are not proxied (a passive learns the original directly).
* Nothing here has been tested in the game client yet.
